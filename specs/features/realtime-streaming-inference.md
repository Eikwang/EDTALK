# 功能需求：实时流式推理服务

## 1. 功能概述

为 EDTalk 开发实时流式推理服务，通过 API 接收流式音频输入，实时驱动数字人嘴部运动，并将合成后的 1080p 画面推流到 UnityCapture 虚拟摄像头。服务启动后循环播放预加载的序列帧，收到音频时实时渲染嘴部并贴回原始帧，无音频时保持嘴部闭合状态。

## 2. 场景与用户

- **主要用户**：需要驱动数字人进行实时口播的应用系统
- **使用场景**：数字人直播、实时对话、虚拟主播等需要音频驱动嘴部运动的场景
- **运行环境**：Windows + NVIDIA GPU + UnityCapture 虚拟摄像头

## 3. 核心流程

### 3.1 服务启动

1. 加载推理模型（Audio2Lip + Generator）
2. 加载默认序列帧包（orifra 原始帧 + cropped 帧 + facemark/metadata 坐标数据）
3. 启动推流循环

### 3.2 推流循环（25fps）

1. 读取当前序列帧的下一帧 orifra（原始 1080p 帧）
2. 读取对应的 cropped 帧（256x256）送入 Encoder 提取 wa + feats
3. 判断音频状态：
   - **有音频**：Audio2Lip 生成 lip 系数 → Generator 渲染嘴部 → 提取嘴部区域 → 贴回 orifra
   - **无音频**：用静音 mel 生成 lip 系数（嘴闭合）→ 同上流程
4. 合成后的 1080p 帧写入 UnityCapture 共享内存
5. 虚拟摄像头输出画面

### 3.3 动态切换序列帧

- 客户端通过 API 请求切换序列帧包
- 加载新的序列帧包（orifra + cropped + facemark/metadata）
- 下一帧直接使用新包渲染，推流不中断

### 3.4 流式音频输入

- 客户端通过 API 持续推送音频片段
- 服务端缓冲音频数据，逐帧消费
- 音频中断时自动切换静音模式

## 4. 验收标准

### Happy Path（正常流程）

**AC-001**: Given 推理服务已启动且至少加载了一个序列帧包，When 服务进入推流循环，Then 以 25fps 持续向虚拟摄像头输出合成后的 1080p 画面，无音频时人物嘴部保持闭合状态。

**AC-002**: Given 推理服务正在推流且无音频输入，When 客户端通过 API 推送一段音频片段，Then 从收到音频后的下一帧起，人物嘴部开始随音频内容运动，端到端延迟低于 1 秒。

**AC-003**: Given 客户端持续推送音频，When 音频片段持续到达，Then 人物嘴部持续跟随音频运动，口型与音频内容同步，无卡顿或跳帧。

**AC-004**: Given 推理服务正在推流，When 客户端通过 API 请求切换序列帧包，Then 从下一帧起直接使用新的序列帧包渲染并推流，推流不中断。

**AC-005**: Given 序列帧包已加载，When 推流循环播放到最后一帧，Then 自动循环回到第一帧继续播放，循环切换无可见跳变。

**AC-006**: Given Generator 渲染出 256x256 人脸帧，When 合成模块执行贴回操作，Then 仅将嘴部区域（基于 facemark 定义的嘴部关键点）提取并贴回 orifra 对应位置，贴回区域与原始帧自然融合，无明显接缝。

### Edge Cases（边界和异常）

**AC-007**: Given 推理服务正在推流，When 客户端停止推送音频（音频流中断），Then 服务自动切换为静音模式，人物嘴部恢复闭合状态，推流不中断。

**AC-008**: Given 客户端推送的音频片段到达速度慢于消费速度，When 音频缓冲区为空，Then 使用静音 mel 填充当前帧，避免推流卡顿。

**AC-009**: Given 客户端推送的音频片段到达速度快于消费速度，When 音频缓冲区接近上限，Then 丢弃最早的音频数据，保留最新音频，避免内存溢出。

**AC-010**: Given 推理服务正在推流，When 切换序列帧包时新旧包的分辨率或方向（横屏/竖屏）不同，Then 推流分辨率自动适配新包，虚拟摄像头输出正确画面。

**AC-011**: Given 推理服务启动时，When 指定的序列帧包路径不存在或数据不完整，Then 服务启动失败并返回明确的错误信息，不进入推流循环。

**AC-012**: Given 推理服务正在推流，When UnityCapture 虚拟摄像头未被任何应用读取，Then 推流循环继续运行不阻塞，帧写入操作跳过或快速超时返回。

### Business Rules（业务规则）

**AC-013**: Given 任何情况下，When 推理服务运行，Then 端到端延迟（从音频推送到虚拟摄像头画面更新）不超过 1 秒。

**AC-014**: Given 任何情况下，When 推流循环运行，Then 输出帧率稳定在 25fps，帧率波动不超过 ±2fps。

**AC-015**: Given 任何情况下，When 嘴部区域贴回 orifra，Then 贴回坐标严格基于预处理阶段记录的 facemark 和 metadata 数据，不得使用运行时重新检测的坐标。

**AC-016**: Given 任何情况下，When 音频缓冲区大小设定，Then 缓冲区上限不超过 2 秒音频数据，防止延迟累积。

## 6. 依赖与约束

- **推理模型**：Audio2Lip（音频→lip系数）+ Generator（lip/pose→渲染帧），模型权重已训练完成
- **推理链路**：参考 `demo_change_a_video_lip.py`，核心调用 `Generator.test_from_audio_pose_image()`
- **虚拟摄像头**：UnityCapture，基于 Windows 共享内存 IPC，Python 通过 ctypes 写入 RGBA 帧数据
- **合成数据**：依赖预处理阶段产出的 orifra（原始帧）、cropped（裁剪帧）、facemark（面部关键点）、metadata（裁剪坐标）
- **GPU**：推理需要 NVIDIA GPU，模型常驻显存
- **帧率**：25fps，与模型训练帧率一致
- **音频格式**：16kHz PCM，与 Audio2Lip 输入要求一致
